# Честное колесо

Адаптивное колесо выбора на React, TypeScript и Vite. Вариант сначала выбирается криптографическим движком, а вращение лишь визуально приводит выбранный сектор к установленной пользователем стрелке.

## Возможности

- два режима: «На выбывание» и «Один выбор»;
- до 100 вариантов, по одному на строку;
- ручное зачёркивание и восстановление вариантов;
- честная перетасовка списка тем же модулем случайности;
- перетаскиваемая мышью или пальцем стрелка по всей окружности;
- плавный разгон и инерционное замедление колеса;
- случайная длительность вращения 7,5–13,5 секунды;
- при двух оставшихся вариантах — финальное вращение 15–20 секунд;
- история результатов и подробный аудит математики выбора;
- изменяемая ширина правой панели на больших экранах;
- адаптивная мобильная раскладка;
- сохранение списка и выбранного режима в `localStorage`.

Горячие клавиши:

- `Space` — запустить колесо;
- `S` — зачеркнуть текущий результат;
- `Esc` — закрыть аудит;
- `←`/`→` на стрелке — передвинуть её на 2°;
- `Shift` + `←`/`→` — передвинуть стрелку на 10°.

## Как выбирается результат

Главный источник случайности — браузерный Web Crypto (`crypto.getRandomValues`). Движок дважды собирает доступные данные, кодирует их с указанием длины каждого значения и смешивает через SHA-256.

В пул могут входить:

- два независимых 256-битных значения Web Crypto;
- Unix timestamp, high-resolution time и микротайминги выполнения;
- движения мыши, касания и интервалы клавиш;
- доступные параметры устройства;
- погода случайного города, влажность, давление и ветер;
- волны и температура океана;
- BTC/ETH и валютные курсы;
- последний блок Bitcoin и номер блока Ethereum;
- солнечная активность NOAA;
- последнее землетрясение USGS;
- радиационный фон Safecast и квантовый источник ANU;
- измеренная задержка ответов сетевых API;
- GPS, микрофон и камера — только после отдельного включения пользователем.

После SHA-256 движок получает `Uint32` и использует rejection sampling. Неполный край диапазона отбрасывается до операции остатка от деления, поэтому modulo bias не даёт отдельным строкам микроскопического преимущества.

Стрелка не выбирает победителя. Пользователь устанавливает её положение, движок независимо определяет индекс варианта, а затем рассчитывает угол остановки так, чтобы уже выбранный сектор оказался под стрелкой. Длительность, количество оборотов и точка внутри победившего сектора влияют только на анимацию.

Кнопка «Перетасовать» использует тот же двухпроходный пул, SHA-256 и Fisher–Yates с unbiased-индексами.

> Публичные данные не считаются тайными или гарантированно неподконтрольными. Криптографической основой остаётся Web Crypto, а внешние источники служат дополнительной примесью. Встроенный аудит объясняет конкретный расчёт, но это клиентское приложение, а не публично проверяемая лотерейная система с предварительной фиксацией seed.

## Локальный запуск

Понадобятся актуальная LTS-версия Node.js и npm.

```bash
npm ci
npm run dev
```

Vite покажет локальный адрес, обычно `http://localhost:5173`.

Production-сборка:

```bash
npm run build
```

Готовые статические файлы появятся в каталоге `dist`.

Локальная проверка production-сборки:

```bash
npm run preview
```

`vite preview` предназначен только для проверки и не должен использоваться как production-сервер.

## Публикация на Ubuntu VPS через Nginx

Ниже используется рекомендуемая для этого проекта схема: сборка выполняется на локальном компьютере, а на VPS отправляется только `dist`. На сервере не нужно устанавливать Node.js или постоянно запускать приложение через PM2.

В примерах замените:

- `deploy` — на имя пользователя VPS;
- `203.0.113.10` — на IP сервера;
- `wheel.example.com` — на свой домен.

### 1. Подготовьте домен

В DNS-панели создайте `A`-запись домена, указывающую на IPv4-адрес VPS. Если сервер использует IPv6, дополнительно создайте `AAAA`-запись. Дождитесь обновления DNS.

### 2. Соберите приложение локально

В каталоге проекта выполните:

```bash
npm ci
npm run build
```

В PowerShell отправьте результат на сервер:

```powershell
scp -r .\dist deploy@203.0.113.10:/tmp/fair-wheel-dist
```

Если такой временный каталог уже существует, сначала переименуйте его или удалите только этот точный каталог на VPS.

### 3. Установите Nginx

Подключитесь к серверу:

```bash
ssh deploy@203.0.113.10
```

Установите Nginx и `rsync`:

```bash
sudo apt update
sudo apt install -y nginx rsync
sudo systemctl enable --now nginx
```

Если используется UFW, сначала сохраните доступ по SSH, затем откройте веб-порты:

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
```

### 4. Разместите статические файлы

```bash
sudo install -d -m 755 /var/www/fair-wheel
sudo rsync -a --delete /tmp/fair-wheel-dist/ /var/www/fair-wheel/
sudo chown -R root:root /var/www/fair-wheel
sudo find /var/www/fair-wheel -type d -exec chmod 755 {} \;
sudo find /var/www/fair-wheel -type f -exec chmod 644 {} \;
```

Перед `rsync --delete` всегда проверьте, что указаны именно `/tmp/fair-wheel-dist/` и `/var/www/fair-wheel/`: команда удаляет из целевого каталога старые файлы, которых нет в новой сборке.

### 5. Настройте Nginx

Создайте файл `/etc/nginx/sites-available/fair-wheel`:

```nginx
server {
    listen 80;
    listen [::]:80;

    server_name wheel.example.com;
    root /var/www/fair-wheel;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location = /index.html {
        add_header Cache-Control "no-cache";
    }

    location ~* \.(?:css|js|svg|png|jpg|jpeg|gif|webp|ico|woff2?)$ {
        try_files $uri =404;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

Активируйте конфигурацию и проверьте её до перезагрузки:

```bash
sudo ln -s /etc/nginx/sites-available/fair-wheel /etc/nginx/sites-enabled/fair-wheel
sudo nginx -t
sudo systemctl reload nginx
```

Если ссылка уже существует, повторно создавать её не нужно. После этого сайт должен открываться по `http://wheel.example.com`.

### 6. Включите HTTPS

HTTPS обязателен для нормальной работы разрешений камеры, микрофона и геолокации. Установите Certbot через Snap:

```bash
sudo snap install core
sudo snap refresh core
sudo snap install --classic certbot
sudo ln -sf /snap/bin/certbot /usr/local/bin/certbot
sudo certbot --nginx -d wheel.example.com
```

Проверьте автоматическое продление сертификата:

```bash
sudo certbot renew --dry-run
```

Теперь приложение должно открываться по `https://wheel.example.com`.

### 7. Обновление приложения

Снова соберите проект локально:

```bash
npm ci
npm run build
```

Загрузите новую сборку во временный каталог с другим именем:

```powershell
scp -r .\dist deploy@203.0.113.10:/tmp/fair-wheel-next
```

На VPS опубликуйте её:

```bash
sudo rsync -a --delete /tmp/fair-wheel-next/ /var/www/fair-wheel/
sudo chown -R root:root /var/www/fair-wheel
```

Перезапуск Nginx для обычного обновления статических файлов не требуется. После проверки временный каталог можно удалить:

```bash
rm -rf /tmp/fair-wheel-next
```

### Диагностика VPS

Проверка конфигурации и состояния Nginx:

```bash
sudo nginx -t
sudo systemctl status nginx --no-pager
```

Последние ошибки:

```bash
sudo journalctl -u nginx -n 100 --no-pager
sudo tail -n 100 /var/log/nginx/error.log
```

Проверка ответа сайта:

```bash
curl -I https://wheel.example.com
```

Если часть внешних источников в аудите отмечена как недоступная, это не обязательно проблема VPS: запросы выполняются напрямую из браузера пользователя, а отдельные публичные API могут временно не отвечать, ограничивать частоту или запрещать CORS. Web Crypto и локальные источники продолжат работать.

## Конфиденциальность и разрешения

- список вариантов и режим хранятся только в `localStorage` браузера;
- приложение не имеет собственного сервера сбора данных;
- GPS, микрофон и камера отключены по умолчанию;
- браузер запрашивает разрешение перед доступом к дополнительным датчикам;
- полученные аудио- и видеоданные не сохраняются: в пул попадают вычисленные характеристики и SHA-256 отпечатки;
- внешние API видят обычный сетевой запрос пользователя и его IP-адрес.
